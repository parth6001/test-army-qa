## Implemented behavior

- `shared/run-result.mjs` and its TypeScript declaration define the validated
  result contract. A pass requires exit 0, no signal/report errors, a positive
  test count, consistent counts, and every actual test result passed.
- `server/run-report.mjs` validates Playwright report identity and totals, walks
  nested suites, preserves test status, and returns structured summary/errors.
  Missing, malformed, mismatched and partial reports never establish success.
- `server.mjs` creates a UUID report path under ignored `.test-army/reports/`.
  `playwright.external.config.ts` embeds that identity from `TEST_ARMY_RUN_ID`.
  Runner exit code/signal and timeout information accompany the summary.
- `shared/event-stream.mjs` handles HTTP errors, missing/wrong response content,
  byte-split UTF-8, CRLF framing, invalid events, error events, early disconnects,
  and missing completion. A five-minute request deadline restores UI controls;
  it does not claim to cancel server-side work.
- `src/App.tsx` renders structured results, separate counts and row statuses,
  run ID, exit information and errors. Console text cannot determine success.
  Starting a rerun clears the previous result. Request errors are shown directly.
- Browser scenarios cover all terminal statuses, HTTP/protocol errors, control
  recovery, edited-code execution and clearing a previous success on rerun.

## Result contract

The final SSE event is `done` with either `{ kind: 'generated' }` (after test code
for review) or `{ kind: 'run', result }`. `result` contains:

```text
runId
status: passed | failed | skipped | timedOut | canceled | noTests | error
tests: title, status, durationMs, error, screenshot
counts: total, passed, failed, skipped, timedOut, interrupted
exitCode: integer or null
signal: string or null
errors: strings
```

Raw `results` text is diagnostic only. Old `report` events / string completions
are rejected rather than silently interpreted by the new frontend. Restart the
backend and reload the frontend together after this change.

Conservative policy: any skipped test prevents an all-pass summary; flaky reports
are errors requiring review; expected-failure tests retain their actual failed
status rather than becoming green. No-tests and infrastructure errors are
distinct. A runner signal or interrupted test is shown as interrupted/canceled;
no Cancel button is added in this task.
