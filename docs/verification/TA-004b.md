# TA-004b — Session authorization

Date: 2026-10-10. Windows, Node v25.6.1. Working-tree implementation, no commit/PR.
Scope and acceptance were recorded in TASKS.md before implementation.

## Implemented behavior

- Local UI bootstraps a cryptographically random session through the existing
  exact Host/Origin/header boundary. Tokens are stored as hashes in the server
  map; the browser retains its token only in an in-memory closure.
- All work/model/cancel/screenshot requests require a bearer token bound to the
  original UI origin. Sessions expire at eight hours, do not survive backend
  restart, and are bounded to 128 entries with 512 jobs per session.
- Jobs are registered to their session at admission. Another session receives
  404 for cancellation and screenshot requests, including known job IDs.
- Screenshot delivery allows only PNG/JPEG/WebP up to 10 MB under the registered
  job artifact directory, rejects links/traversal/non-images, and uses no-store,
  nosniff and a restrictive CSP. No generic static artifact route remains.
- The UI fetches authorized image bytes and uses/revokes a blob URL. Tokens do
  not enter image URLs, localStorage/sessionStorage, provider inputs or run code.
- A 401 clears the browser's cached token. The failed request is not retried;
  the next user action bootstraps a new session. Bootstrap has a 15-second limit;
  credentialed fetches reject redirects and unrelated addresses.

## Limits and remaining work

This is local browser-session isolation, not Windows-user authentication. The
bootstrap permits approved local UI origins. It does not defend against hostile
programs with access to the host/browser memory. Existing completed artifacts
are intentionally inaccessible after session expiry, UI reload or backend restart.
An already admitted task retains its normal four-minute deadline even if its
session expires; expiry blocks new requests, including cancellation.

The worker still runs generated code with host access. Session ownership and file
checks are not an OS sandbox against that code. TA-004c must supply restricted
execution, secret-free worker environment, destination/redirect enforcement and
provider-data minimization. TA-002/003 real runner/process cleanup reviews remain
separate; session fixtures do not establish their acceptance criteria.
